# Навык reglament

Ведёт задачу по регламенту проекта
(`docs/vault/_meta/Регламент.md` — источник истины).

## Табло задачи — обновлять на каждом шаге

`.claude/task-state.json` (локальное, вне git) — машиночитаемое
состояние: задача, путь к заметке, фаза, форма, отметка одобрения.
Фазы: `vault` → `заметка` → `согласовано` → `код` → `тесты` →
`коммит` → `закрыто`.

Хуки читают именно табло: `gate_edit.py` (блок правок кода до
одобрения), `check_commit.py` (блок коммита без ссылки и запуска
штампа ассистентом), `validate_vault.py`, `close_task.py`.

## Вводная памятка (первым сообщением)

Короткая (по умолчанию): задача, форма (полная/малая), фаза,
предупреждение «код не правится до согласования заметки».

Полная (карта файлов системы: устав, vault, память, статус) —
только если память ИИ проекта пуста или по слову «памятка».

## Продолжение прерванной задачи

Незакрытая задача в табло (или «/reglament продолжить»):
прочитать табло → сверить с реальностью (заметка, `git status`,
`current_task.md`) → доложить «в работе „…", фаза „…", продолжаю
с шага N». Табло расходится с реальностью — спросить
пользователя, не угадывать.

## Шаги процедуры

0. **Статус.** Табло + `current_task.md` + `git status` (чужие
   правки — выяснить у пользователя). Завести табло задачи:
   фаза `vault`.

1. **Сначала vault, потом код** (принцип 2). Прочитать README,
   Регламент, связанные заметки — и только потом исходники.

2. **Оценить размер** (принцип 3).

   **Малая форма** — 1–2 файла, без бизнес-правил, зависимостей
   и миграций: сказать «это малая форма, делаю так-то» →
   подтверждение пользователя → фаза `согласовано`; после коммита
   закрыть `close_task.py --desc ... --files ...`

   **Косметика** — форматирование, опечатки, линтер, откат своей
   ошибки: процедура не нужна, сделать и сообщить по факту,
   в коммите метка-исключение.

   **Полная форма** — иначе. Показать ПРОЕКТ заметки по шаблону
   `_meta/Шаблон — задача.md`. Секция «Как проверим» обязательна;
   недосказанное — маркер «⚠️ уточнить», с маркерами не
   согласовывать. Фаза → `заметка`. **Не сохранять заметку, не
   править код.**

   Форму определяет ассистент; при сомнении — брать строже.

3. **Согласование** (полная форма). После устного «согласовано»
   показать команду штампа отдельным bash-блоком (у пользователя
   будет кнопка Run):

       python .claude/hooks/approve_task.py

   Ассистенту запуск запрещён хуком — не пытаться. СРАЗУ после
   показа поставить фонового наблюдателя (инструмент Bash,
   `run_in_background`), чтобы работа продолжилась сама и
   пользователю не пришлось писать в чат после нажатия Run:

       for i in $(seq 1 290); do grep -q '"одобрено": true' \
         .claude/task-state.json 2>/dev/null && exit 0; \
         sleep 2; done; exit 1

   Завершение наблюдателя будит ассистента. Проснувшись: сверить
   табло (отметка стоит; уведомление — сигнал, истина — табло),
   сохранить заметку со статусом `в работе`, фаза → `код`.
   Вышел таймаут (~10 минут) — доложить и перезапустить ожидание.

   Ход, ожидающий штампа, завершать ЯВНЫМ призывом: «Жду вашего
   действия: нажмите Run на блоке выше»; формулу «писать в чат
   не нужно» использовать только вместе с призывом, не вместо
   него. При таймауте показать блок штампа заново и повторить
   призыв.

4. **Код.** По ходу обновлять заметку при смене решений.
   Технические развилки решать самому, пользовательские —
   спрашивать (принцип 7). Объяснять обычными словами:
   пользователь не программист.

5. **Тесты.** Команда тестов — см. `CLAUDE.md`, секция «Запуск
   тестов». Все зелёные ДО коммита; хук прогонит их ещё раз и
   заблокирует красные. Фаза → `тесты`.

   ⚠️ Стек пока не выбран: хук `pre-commit-tests.sh` содержит
   заглушку, которая всегда проходит. После выбора стека
   заменить её реальной командой и вписать команду в `CLAUDE.md`.

6. **Коммит.** В сообщении — ссылка `vault: «Имя заметки»`, или
   пометка `журнал мелких правок`, или метка-исключение
   (косметика / линтер / опечатка / откат) — иначе хук не
   пропустит. Фаза → `коммит`.

7. **Закрытие.** Руками — содержательное: «Как проверим»
   пройдена фактически; изменившиеся решения отражены в заметке;
   память обновлена (`current_task.md`). Бухгалтерию делает
   скрипт:

       python .claude/hooks/close_task.py

   (малая форма: `--desc "что сделано" --files "какие файлы"`) —
   хэш и статус в заметку или строка в журнал, закрывающий
   коммит, табло очищено.

   После крупной задачи предложить `/consolidate-memory`.

## Что НЕ требует процедуры

Косметика, фиксы линтеров, опечатки, откаты своих ошибок,
автоген-файлы. В коммите поставить метку-исключение — иначе
хук заблокирует.

## Особенности проекта

- **Пользователь не программист.** Объяснять решения обычными
  словами, техническую часть брать на себя. Предлагая вариант —
  называть последствия простым языком.
- **Многопользовательский режим** (семья) учитывать в модели
  данных с самого начала.
- **Хостинг платный** — расходы согласовывать заранее.
- **Деплой** — только по явной просьбе пользователя.
