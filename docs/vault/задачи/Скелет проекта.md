# Скелет проекта

## Зачем

Решения приняты на бумаге (требования, стек) — теперь нужен
запускающийся проект. После этой задачи каждая следующая
правит работающую систему, а не пустую папку: сайт открывается,
тесты гоняются, хук тестов начинает работать всерьёз.

## Что именно делаем

Пустой, но живой каркас по выбранному стеку:

1. **Проект Django** с настройками из переменных окружения:
   одна и та же папка работает на машине пользователя и на
   сервере, различия — в переменных, не в коде.
2. **Два способа запуска:**
   - простой — только Python: сайт и тесты работают сразу,
     база — временная локальная (SQLite), планировщика нет.
     Этим же способом хук гоняет тесты перед коммитом;
   - полный — Docker: сайт + PostgreSQL + Redis + планировщик
     Celery, ровно как на будущем сервере.
3. **Страница-заглушка** на главной: название системы и
   подтверждение, что всё живо.
4. **Админка** с пользователем — можно зайти и посмотреть.
5. **Первые тесты** (pytest): главная отвечает, админка на
   месте. С этого момента красный тест блокирует коммит.
6. **Мелочь по хозяйству:** .gitignore для Python, пример
   файла настроек (.env.example), секция «Структура проекта»
   в уставе, примеры автоген-файлов в принцип 8 Регламента
   (миграции Django, lock-файлы зависимостей).

Решение при согласовании: пользователь ставит Docker Desktop
параллельно с разработкой; полный способ проверяется, как
только Docker готов.

## Затрагивает

Новые файлы проекта (config/, tests/, manage.py,
pyproject.toml, Dockerfile, docker-compose.yml, .env.example);
CLAUDE.md (структура, команды запуска); Регламент (примеры
автогена); .claude/hooks/pre-commit-tests.sh (использовать
окружение .venv); эта заметка.

## Бизнес-правила

Новых нет — задача инфраструктурная. Модель данных
(обязательства, счётчики) — следующая задача.

## Как проверим

- дано: папка проекта на машине пользователя → когда: запуск
  тестов → тогда: все зелёные

- дано: запущен простой способ → когда: открыть
  http://localhost:8000 → тогда: страница с названием системы

- когда: открыть http://localhost:8000/admin → тогда: форма
  входа; логин и пароль пользователя пускают внутрь

- дано: установлен Docker Desktop → когда: docker compose up →
  тогда: тот же сайт, но с PostgreSQL и планировщиком; после
  перезапуска созданный пользователь не пропал

- дано: тест намеренно сломан → когда: попытка коммита →
  тогда: хук блокирует (проверяется один раз, потом чинится)
