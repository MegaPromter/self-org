# Счётчик в форме дела: без создания на лету

## Зачем

Поле «название нового счётчика» стоит под списком счётчиков
и читается как обязательное продолжение анкеты: при уже выбранном
«пробег (км) — Hyundai Tucson» туда вписали «Пробег», и форма
создала бы второй счётчик. Единственный случай, когда поле нужно,
редкий: первое дело по пробегу у предмета без счётчика. Для него
есть справочники.

## Что именно делаем

1. Из формы дела убираются «название нового счётчика» и «в чём
   измеряется». Счётчик только выбирается из списка. Создание
   счётчика остаётся в справочниках.
2. Под списком счётчиков подсказка «Нет нужного счётчика? Создайте
   его в справочниках» со ссылкой на страницу создания счётчика.
3. Правила заметки [[Счётчик в форме дела]] о названии из цифр
   и обязательной единице уходят вместе с полями.
4. Предмет и человек из формы создаются как раньше.

## Затрагивает

- `core/forms.py` — поля, проверки, сохранение
- `core/templates/core/form.html` — блок счётчика
- `tests/test_zavedenie.py` — тесты
- [[Заведение данных без админки]] — пункт 4 и правило 3 больше
  не касаются счётчика (запись в истории той заметки)

## Бизнес-правила

1. **Дело «по счётчику»** (или «ещё и по счётчику») сохраняется
   только с выбранным существующим счётчиком. Иначе ошибка
   «Выберите счётчик. Нет нужного — создайте его в справочниках»
   со ссылкой, дело не создаётся.
2. **«Текущее показание» и «показание тогда» без счётчика** →
   ошибка, как сейчас.
3. **Счётчик от другого предмета** не пройдёт: прежняя проверка
   модели.

## Как проверим

- дано: форма нового дела → когда: открыта → тогда: полей «название
  нового счётчика» и «в чём измеряется» нет, под списком счётчиков
  ссылка на создание в справочниках
- дано: «по счётчику», счётчик не выбран → когда: «Сохранить» →
  тогда: ошибка со ссылкой, дело не создано
- дано: «по счётчику», выбран «пробег», «каждые» 60 000, последний
  раз 31.08.2026 при 118 000 → когда: сохранено → тогда: в карточке
  «через 59 600 км»
- тесты pytest зелёные до коммита
