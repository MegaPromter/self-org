# Telegram-бот

## Зачем

Планировщик уже готовит напоминания, но они копятся в журнале
со статусом «ожидает» — увидеть их можно только в админке.
Эта задача доводит цепочку до конца: напоминания приходят
в Telegram, и прямо из сообщения — кнопками — можно отметить
«сделано», отложить или ввести показание, не открывая сайт.
Это ядро удобства первой версии (правило 12 анализа).

## Что именно делаем

1. **Канал отправки.** Бот втыкается в разъём планировщика
   (`register_channel`): готовое уведомление уходит сообщением
   в Telegram. В сообщении — текст напоминания, фактура
   обязательства (артикул, где лежит, цена…) и кнопки.
2. **Кнопки.** «Сделано» — записывает выполнение; «Отложить» —
   молчать день / 3 дня / неделю; «Ввести показание» — бот
   спрашивает число и записывает его в счётчик.
3. **Привязка чата.** В админке на странице настроек уведомлений —
   ссылка «Подключить Telegram». Клик открывает бота, бот
   запоминает чат и подтверждает. Чужим бот не отвечает по делу —
   только просит код привязки.
4. **Защита от пачки залежавшихся** (хвост из задачи
   [[Планировщик]]): уведомление, простоявшее «в ожидании» больше
   суток, помечается «устарело» и не отправляется. Актуальные
   напоминания планировщик создаст заново сам.

**Что понадобится от пользователя:** создать бота у @BotFather
в Telegram (бесплатно, пара минут — ассистент даёт пошаговую
инструкцию) и передать токен. Расходов нет.

## Затрагивает

- новое: `core/telegram.py` — отправка, бот, кнопки;
  `core/bot_actions.py` — действия кнопок отдельно от телеграмной
  обвязки (для тестов); команда `manage.py run_bot`
- `core/models.py` + миграция — у обязательства поле «отложено
  до»; у уведомления статус «устарело»
- `core/planner.py` — учёт «отложено до», устаревание, поправка
  дедупликации
- `core/apps.py` — регистрация канала при старте
- `config/settings.py` — токен из переменной окружения
- `docker-compose.yml` — служба бота; `pyproject.toml` —
  зависимость `python-telegram-bot`
- админка — ссылка привязки, поле «отложено до»
- `tests/` — тесты действий кнопок, устаревания, отложки

## Бизнес-правила

**Отправка:**

1. Уведомление уходит в привязанный чат получателя: текст
   напоминания + строки фактуры обязательства + кнопки.
   У «скоро»/«просрочено» кнопки «Сделано» и «Отложить»,
   при правиле по счётчику — ещё «Ввести показание».
   У «введите показания» — только «Ввести показание».
2. Чат не привязан — уведомление остаётся «ожидает» и уйдёт
   после привязки (если не устареет).
3. **Устаревание:** не отправленное за сутки после «не раньше»
   помечается «устарело». Устаревшие не считаются при защите
   от дублей — планировщик создаст свежее напоминание следующим
   прогоном, если тема ещё актуальна.

**Кнопки:**

4. «Сделано» — выполнение с сегодняшней датой; если правило
   по счётчику — записывается текущее расчётное показание.
   Бот подтверждает и предлагает ответным сообщением прислать
   стоимость (число) — она допишется в выполнение. Не прислали —
   ничего страшного, можно в админке.
5. «Отложить» — выбор: 1 день / 3 дня / неделя. До выбранной
   даты планировщик молчит об этом обязательстве, потом
   напоминает как обычно.
6. «Ввести показание» — бот просит число, ответ записывается
   показанием счётчика с сегодняшней датой.
7. Кнопки и команды работают только из привязанного чата.
   Незнакомый чат получает вежливый отказ, данные не меняются.

**Привязка и запуск:**

8. Ссылка «Подключить Telegram» в админке содержит подписанный
   код — подделать нельзя. Отвязка — очистить поле chat id
   в админке.
9. Токен бота — из переменной окружения. Токена нет — сайт
   и планировщик работают как раньше, уведомления копятся.
10. Бот — отдельный процесс: `manage.py run_bot` при простом
    запуске, отдельная служба в Docker. Режим — опрос Telegram
    (long polling): работает с домашнего компьютера, доступ
    извне не нужен.

## Как проверим

- дано: «Масло ДВС» просрочено, фактура «артикул — 152089E42A»,
  чат привязан → когда: прогон планировщика → тогда: в Telegram
  сообщение с текстом, артикулом и кнопками, в журнале статус
  «отправлено»
- дано: сообщение с кнопками → когда: нажато «Сделано» → тогда:
  в истории обязательства выполнение с сегодняшней датой
  и расчётным пробегом, бот подтвердил
- дано: подтверждение «пришлите стоимость» → когда: ответ
  «3500» → тогда: стоимость записана в это выполнение
- дано: нажато «Отложить» → «неделя» → когда: прогоны в течение
  недели → тогда: новых напоминаний нет; после — приходят снова
- дано: напоминание «введите показания» → когда: «Ввести
  показание» и ответ «118500» → тогда: показание счётчика
  на сегодня записано
- дано: в журнале уведомления «ожидает» трёхдневной давности →
  когда: подключается бот → тогда: пачка не приходит,
  они «устарело»; свежие (моложе суток) приходят
- дано: посторонний пишет боту → когда: любая команда или
  кнопка → тогда: отказ, ничего не записано
- тесты pytest зелёные до коммита
