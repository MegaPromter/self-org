# Счётчик в форме дела: подписи и текущее показание

## Зачем

В форме дела блок счётчика сбивает с толку: в «…или новый счётчик»
тянет вписать число (так на обкатке появился счётчик с названием
«118400»), поле «в чём измеряется» при выбранном существующем
счётчике молча пропадает, а само текущее показание ввести негде —
за ним нужно идти на главную.

## Что именно делаем

1. Подпись «…или новый счётчик» → «название нового счётчика»,
   подсказка «Словом, не числом: пробег, моточасы, вода холодная».
   Название из одних цифр форма не примет: «Это похоже на показание,
   а не на название. Показание — в поле «текущее показание»».
2. Поле «в чём измеряется» показывается только когда вводится новый
   счётчик. У существующего единица видна прямо в списке выбора:
   «пробег (км) — Hyundai Tucson».
3. Новое поле «текущее показание» в блоке счётчика, подсказка
   «Что на счётчике сейчас, например 118 400. Запишется как показание
   на сегодня». При правке дела заранее заполнено последним известным
   показанием.
4. Попутно чинятся данные обкатки: счётчик «118400» переименован
   в «пробег», записано показание 118 400 на сегодня.

## Затрагивает

- `core/forms.py` — поля, проверки, сохранение показания
- `core/templates/core/form.html` — порядок полей, скрытие единицы
- `tests/test_zavedenie.py` — тесты на новые правила

Модель и миграции не меняются. См. [[Заведение данных без админки]].

## Бизнес-правила

1. **Текущее показание** записывается тем же способом, что кнопка
   «Ввести показание» (общая функция), датой сегодня. Пустое поле
   или значение, равное последнему показанию, записи не создаёт:
   открыл-сохранил без правок → история показаний не растёт.
2. **Показание меньше последнего** не запрещается (как и у кнопки):
   после сохранения показывается предупреждение «показание меньше
   предыдущего (N) — проверьте».
3. **Текущее показание без счётчика** → ошибка, как сейчас
   у «показания тогда».
4. **Название нового счётчика из одних цифр** (с пробелами
   и точками) → ошибка, введённое не теряется.
5. **Единица существующего счётчика** из формы дела не меняется
   (для этого есть справочники); у нового — обязательна, как сейчас.
6. **Состояние дела «по счётчику» без отметки выполнения** остаётся
   «нет данных»: текущее показание говорит, где счётчик сейчас,
   а не когда дело делали. Для этого есть «когда делали последний
   раз» и «показание тогда».
7. **Без JavaScript** видны все поля, проверки на сервере.

## Как проверим

- дано: новое дело «по счётчику», в «название нового счётчика»
  введено «118400» → когда: «Сохранить» → тогда: ошибка «похоже
  на показание», поля не очистились, счётчика в базе нет
- дано: новое дело, новый счётчик «пробег», «км», текущее показание
  118 400 → когда: сохранено → тогда: счётчик создан, в его истории
  показание 118 400 сегодняшним числом
- дано: правка «Замены ДВС» с выбранным счётчиком → когда: открыта
  форма → тогда: поля единицы нет, в списке «пробег (км) — Hyundai
  Tucson», в «текущем показании» стоит 118 400
- дано: та же форма → когда: сохранена без правок → тогда: в истории
  показаний по-прежнему одна запись; изменено на 118 900
  и сохранено → две
- дано: та же форма, введено 100 000 → когда: сохранена → тогда:
  запись есть, наверху предупреждение «меньше предыдущего»
- тесты pytest зелёные до коммита
