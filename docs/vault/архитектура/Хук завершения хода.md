# Хук завершения хода

## Зачем

Дважды повторялся один сбой: ассистент показывал команду штампа,
пользователь нажимал Run — и сессия молчала, потому что ассистент
забывал запустить фонового наблюдателя за табло. Приходилось
писать в чат вручную. Забывчивость не лечится текстом инструкции —
только скриптом (принцип 10 регламента плагина).

## Решение

Хук `check_turn_end.py` на событие Stop (ассистент закончил ход).
В фазе «заметка», пока согласования нет, ход не заканчивается
молча: если последнее сообщение не вопрос и карточка согласования
не задана, хук разворачивает ассистента с инструкцией задать её.

Ход-вопрос пропускается: согласование ещё обсуждается. Защита
от цикла — встроенный `stop_hook_active` (после 8 блокировок
Claude Code перебивает хук сам).

## Как согласование устроено сейчас

С версии плагина 1.4.3 штампа нет. Согласование — **клик
пользователя по варианту «Согласовано» в карточке вопроса**
(инструмент AskUserQuestion). Ответ приходит тем же ходом:
ни терминала, ни кнопки Run, ни ожидания и пробуждения сессии.

Истина о согласовании лежит не в табло, а в стенограмме сессии:
её пишет Claude Code, ассистент подделать её не может. Правило
поиска записано один раз в `gate_edit.py`; `check_turn_end.py`
берёт его импортом, чтобы не разошлись две копии. Найдя ответ,
`gate_edit.py` сам ставит отметку в табло — чтобы задача,
продолженная в новой сессии, не согласовывалась заново.

Название задачи в тексте вопроса привязывает согласование
к текущей задаче: «Согласовано» от прошлой задачи не засчитается.

## Файлы

- `.claude/hooks/check_turn_end.py` — сам хук;
- `.claude/hooks/gate_edit.py` — правило поиска согласования;
- `.claude/settings.json` — секция Stop (без matcher: событие
  его не поддерживает).
