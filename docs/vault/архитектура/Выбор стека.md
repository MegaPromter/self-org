# Выбор стека

## Зачем

Требования собраны (см. [[Анализ требований и разбор аналогов]]),
решено писать своё. Теперь надо выбрать инструменты — язык,
фреймворк, базу данных, способ запускать напоминания по
расписанию. Решение на годы: пользователь не программист
и не сможет переписать систему сам, а переезд на другой стек
позже стоит дороже, чем месяцы первоначальной работы.

## Исходные данные

- **Бюджет сервера:** 500–800 ₽/мес.
- **Домен:** `managesystems.ru` — уже есть.
- **Сервер зарубежный** — Telegram доступен без ухищрений.
- **Опыт пользователя:** проект `planapp_django` — работа
  с нейросетью; Django видел, но программистом себя не считает.
- **Требуется:** веб-интерфейс для телефона, Telegram и почта,
  расчёт сроков по счётчикам и датам, многопользовательский
  режим в модели данных.

## Что именно выбираем

Пять решений, каждое со своими последствиями:

1. Язык и фреймворк — на чём написана система.
2. База данных — где хранятся дела и показания.
3. Планировщик — что запускает проверку сроков по часам.
4. Библиотека Telegram — как бот общается с пользователем.
5. Способ развёртывания — как система попадает на сервер.

## Затрагивает

Эта заметка; `CLAUDE.md` (секции «Стек», «Запуск проекта»,
«Запуск тестов»); `.claude/hooks/pre-commit-tests.sh` (замена
заглушки реальной командой с защитой на период, пока кода нет);
`docs/vault/README.md` (состояние проекта).

## Рассмотренные варианты

### Django (Python) — выбран

**Что даёт из коробки:** админка (готовый экран для правки
любых данных — можно пользоваться, пока не готов основной
интерфейс), система пользователей и паролей, миграции базы,
защита от типовых атак.

**Почему подходит именно здесь:**

- **Админка снимает месяцы работы.** Заводить предметы,
  обязательства и интервалы можно сразу, не дожидаясь красивых
  экранов. Для системы, где половина работы — правка справочных
  данных, это решающе.
- **Опыт пользователя.** `planapp_django` — знакомая территория,
  ниже порог для чтения кода.
- **Многопользовательский режим встроен.** Пользователи, права,
  разграничение доступа — не пишутся руками.

**Минусы честно:** тяжелее «лёгких» фреймворков, часть
возможностей останется неиспользованной. Для одного
пользователя это избыточно — но горизонт семейный.

### FastAPI (Python) — отклонён

Современный, быстрый, хорош для программных интерфейсов.

**Почему не подходит:** нет админки. Разработчики, переходившие
с Django, сообщают, что готовые надстройки закрывают около 60 %
её возможностей — остальное пишется руками. Нет встроенной
системы пользователей. Для задачи, где нужен полноценный сайт
с формами и разграничением доступа, это месяцы лишней работы
ради скорости, которая здесь не нужна: система обслуживает
одну семью, а не тысячи запросов в секунду.

### Node.js, PHP, Go — отклонены

Работоспособны, но проигрывают по совокупности: у пользователя
нет опыта, готовой админки такого уровня нет, а преимущества
(скорость, единый язык с интерфейсом) для этой задачи
несущественны.

## Принятые решения

| Что | Выбор | Почему |
|---|---|---|
| Язык | Python | опыт пользователя; богатая экосистема |
| Фреймворк | Django | админка, пользователи, миграции из коробки |
| База данных | PostgreSQL | надёжна, бесплатна, растёт вместе с проектом |
| Планировщик | Celery + Celery Beat | проверенное расписание, переживает перезапуск |
| Telegram | python-telegram-bot | для личного бота с командами — достаточно и проще |
| Развёртывание | Docker Compose | одинаково на машине пользователя и на сервере |
| Веб-сервер | Caddy | https на managesystems.ru, сертификат получает и продлевает сам |

### Отдельно про планировщик — почему не встроенный Django

Django 6.0 (декабрь 2025) получил встроенные фоновые задачи,
и напрашивалось взять их. **Не подходит:** встроенный механизм
умеет только разовый запуск, расписания в нём нет вообще.
Система напоминаний целиком построена на расписании — значит,
нужен Celery Beat либо надстройка `django-scheduled-tasks`.
Берём Celery: проверен годами, переживает перезапуск сервера,
умеет повторять неудавшиеся попытки.

### Отдельно про базу — почему не SQLite

SQLite проще: файл вместо отдельной программы, дешевле по
памяти. **Не берём:** плохо переносит одновременную запись
(бот, сайт и планировщик пишут разом), а переезд на PostgreSQL
позже — отдельная работа с риском потерять данные. Дешевле
взять сразу.

## Во что это обойдётся

**Сервер.** Нужно примерно 2 ядра и 4 ГБ памяти: Django,
PostgreSQL, Celery и бот работают одновременно. В бюджете
500–800 ₽/мес это достижимо у европейских провайдеров
(Fornex — от 600 ₽, Timeweb — площадки во Франкфурте
и Амстердаме). Точный выбор — отдельная задача при развёртывании.

**Прочее:** домен есть, сертификат бесплатный (Caddy получает
сам), Telegram бесплатен, почта — через бесплатный тариф
почтового сервиса либо тот же сервер.

**Итого:** в рамках объявленного бюджета, без скрытых расходов.

## Как проверим

- дано: решение принято → когда: пользователь читает таблицу
  «Принятые решения» → тогда: по каждой строке понимает,
  что выбрано и почему, без технических терминов без пояснений

- дано: раздел «Во что это обойдётся» → когда: пользователь
  читает → тогда: видит, что расходы укладываются в 500–800 ₽
  в месяц, и знает, за что платит

- дано: разделы про планировщик и базу → когда: пользователь
  читает → тогда: понимает, почему отвергнуты более простые
  варианты (встроенные задачи Django, SQLite)

- дано: стек выбран → когда: заводится следующая задача →
  тогда: в `CLAUDE.md` заполнены секции «Стек», «Запуск
  проекта», «Запуск тестов», а заглушка тестов в хуке заменена
  реальной командой
