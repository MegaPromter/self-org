# Self-org — система персональной организации

Хранит регулярные и разовые обязательства (хозяйство, машина, дом,
родня, финансы, общественное), знает даты и интервалы, заранее
напоминает в Telegram. Рядом с задачей — фактура: где лежит, номер,
цена, дата заказа. Горизонт: доступ извне, многопользовательский
режим для семьи.

## Регламент документации

Полный текст: `docs/vault/_meta/Регламент.md` — источник истины.
Кратко:

1. Документация — в `docs/vault/` внутри репозитория.
2. Перед задачей: сначала читать vault, потом код.
3. На любое требование — сначала проект заметки в чат, согласование,
   и только потом сохранение.
4. **Никакого кода без согласованной заметки.**
5. В коммите — ссылка на заметку.
6. После выполнения — хэш коммита в заметку.
7. При сомнении — остановиться и спросить пользователя.
8. Автогенерируемые файлы — исключение из правил 3/5/6.
9. Незакрытая задача — обновить `current_task.md` в конце сессии.

Начало каждой задачи: `/reglament`.

## Стек

Решение с обоснованием: `docs/vault/архитектура/Выбор стека.md`.

- Python + Django — сайт, админка, пользователи
- PostgreSQL — база данных
- Celery + Celery Beat — напоминания по расписанию
- python-telegram-bot — бот
- Docker Compose — развёртывание; Caddy — https на managesystems.ru

## Запуск проекта

- Простой (без Docker): `.venv\Scripts\python manage.py runserver`
  → http://localhost:8000 — сайт и админка, база SQLite.
- Telegram-бот (отдельным окном): `.venv\Scripts\python manage.py
  run_bot`. Нужен токен от @BotFather в переменной окружения
  `TELEGRAM_BOT_TOKEN`; имя бота — в `TELEGRAM_BOT_USERNAME`
  (тогда в админке появится ссылка привязки чата).
- Полный: `docker compose up` — сайт + PostgreSQL + планировщик
  Celery + бот, как на сервере.

## Запуск тестов

`.venv\Scripts\python -m pytest -q` — хук гоняет их перед каждым
коммитом сам (использует .venv автоматически).

## Структура проекта

```
config/         настройки Django, точки входа, Celery
tests/          тесты (pytest)
docs/vault/     документация (регламент, задачи, модули, архитектура)
.claude/        навык /reglament, хуки, табло задачи
manage.py       служебные команды Django
pyproject.toml  зависимости и настройка тестов
docker-compose.yml  полный локальный запуск / основа сервера
```
Приложения Django будут добавляться в корень по мере задач.

## Конвенции кода

- Язык общения, комментариев в коде и документации — **русский**.
- Комментарии объясняют «зачем», а не «что».
- Имена переменных и функций — по стандарту выбранного языка.

## Развёртывание и ограничения

- Работает на арендованном сервере, доступ извне — обязателен.
- Многопользовательский режим (семья) — учитывать в модели данных
  с самого начала, даже если сперва пользователь один.
- Уведомления — Telegram; архитектура должна допускать другие каналы.
- Хостинг платный — расходы согласовывать с пользователем.

## Правила работы

- **Пользователь не программист** (базовые понятия). Объяснять решения
  обычными словами, без жаргона; техническую часть брать на себя.
  Предлагая вариант — называть последствия простым языком.
- Коммит — со ссылкой на заметку vault. Тесты зелёные до коммита.
- Деплой — только по явной просьбе пользователя.
- Стиль общения: коротко, по делу, без воды. Сомневаешься — спроси.
